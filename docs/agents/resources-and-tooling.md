## Repository purpose

This repository contains **reusable, project-agnostic review checklist templates**. A checked box in a project-specific copy represents verified work; the unchecked templates in this repository **do not certify** a product. Use the checklists for suitable web applications, APIs, content sites, AI products, and other software projects. Applicability varies by project and jurisdiction.

## Generated website

The `website/` directory contains the static-site generator, responsive assets, an introductory `llms.txt` template, and build/deployment documentation. Run `bash website/build.sh` to convert every applicable repository Markdown file into HTML and produce navigation, search, SEO metadata, a sitemap, robots.txt, and the generated root `llms.txt`. The `website/dist/` output is ignored by Git. Website build CI remains disabled (`.github/workflows/website.yml.disabled`); source lint is also disabled (`.github/workflows/checklist-lint.yml.disabled`). Neither legacy workflow runs on pushes, pull requests or schedules; curation and link-health workflows operate separately. Build and validate locally with `bash website/build.sh` and `python website/check_site.py`. Cloudflare Pages deploys the `main` branch to https://awesome-checklists.pages.dev/; set `SITE_URL` to the actual published origin and path. Website source and artifacts do not count as checklist files or checklist IDs.

**Source-reference ordering:** Every numbered checklist must end with a genuine `**Source review date:** YYYY-MM-DD` line and may not append vendor tools, new reference URLs or other content after that date. Use the [central optional testing-tool index](../../lists/references/optional-testing-tools.md) for domain-specific suggestions and keep citations immediately above the date. `validate_sections.py` enforces this editorial invariant.

**Resource routing rule:** If every actionable recommendation is already covered, cite the existing checklist IDs and retain the source in the relevant worksheet/audit instead of adding duplicate checks. Add or strengthen a check only when a distinct, independently verifiable gap remains. For example, the migration worksheet's documented Google Search Console Change of Address applicability was integrated into **SEO-032**; the reusable URL map remains optional.

**All-prefix integrity:** Regenerate and locally check `lists/references/id-prefix-ranges.json` via `generate_id_prefixes.py --check`. This covers 35 ID prefixes and all owning scopes, complementing the SEC registry and AGENT cross-scope contract. Do not silently retire or renumber controls.

**Reproducibility and freshness:** `checklists.py` defaults to an immutable source SHA and explicitly rejects `--repo-root` with `--ref`. Every review must record the exact checklist-source SHA and reviewed project revision. The [generated inventory](../../lists/references/inventory.json) and [source age policy](../../lists/references/source-freshness-policy.md) have offline verification scripts. [Security surface coverage](../../lists/references/security-surface-coverage.md) locates relevant frontend/backend controls. Legacy source and website workflows remain disabled. New curation/link-health workflows are scoped checks; for substantive checklist or skill changes, run local checks and follow [CONTRIBUTING.md](../../CONTRIBUTING.md).

**AGENT continuity and MCP currency:** There are 141 AGENT IDs across the AI general/frontend slice and backend API slice; the 22 `AGENT-095`–`AGENT-116` IDs are NOT missing. The structural [contract](../../lists/references/agent-domain-contract.json) and `validate_domain_structure.py` must pass. Do not require a nonexistent API heading in the AI file. MCP 2026-07-28 is the current stable release as of 2026-11-15, but real SDKs may negotiate older versions; confirm exact runtime behavior before asserting conformance. Domain-specific test tools belong in [optional reference](../../lists/references/agent-testing-tools.md).

**Authorship and validation:** [AUTHORSHIP.md](../../AUTHORSHIP.md) discloses AI-assisted work and the lack of an independently reviewed per-ID ledger. New controls need recorded source/version, actual human reviewer when reviewed, validation method and unresolved limitations; never invent an approval. A scoped generated review is always UNKNOWN-first; confirmed external standard IDs are only *proposed partial* mappings until reviewed.

**Contribution policy:** Public repository. Substantive checklist, security, agent-skill and automation changes should use pull requests, recorded local validation and suitable review. An exceptional maintainer direct push is not peer-reviewed or independently validated. See [CONTRIBUTING.md](../../CONTRIBUTING.md).

**2026-11-15 atomicity update:** SEC-009/SEC-116 separate idle and absolute session lifetime; SEC-010/SEC-117 separate password guessing and credential stuffing. AGENT-043 covers operation-specific permissions only, with human approval under existing distinct AGENT IDs. No prior PASS under old compound wording automatically applies to the split checks. Current source inventory is 91 files / 4,215 IDs.

**Inventory and publishing:** There are **91 numbered scope files / 4,215 unique checks** in `lists/`, including `lists/frontend/`, `lists/backend/` and `lists/AI/`. Only numbered `NN_*.md` files in those four scope locations count as checklists; files in `lists/references/` and `lists/frontend/references/` are informational. The website generator exposes unnumbered references as **Resources**. Keep the root `README.md` and relevant checklist links current, and keep `website/` for build scripts, styles/assets, site documentation and generated output.

**Reference-entry quality bar:** Retain the original source URL, author/publisher and date when known, date reviewed, actual use case, documented capabilities, prerequisites/permissions, primary verification, platform/privacy concerns, uncertainty and outcome. Distinguish documented, tested, experimental and unavailable claims; do not imply tools were installed, websites accessed or results independently benchmarked without evidence. Summarize third-party content, retain stable IDs and history, and fix relative links after relocations.

## Installable coding-agent skill

The standard Agent Skills package is at `skills/awesome-checklists/SKILL.md`, with scope mapping at `skills/awesome-checklists/references/domain-selection.md`, a Python 3.10+ standard-library GitHub/local-source reader at `skills/awesome-checklists/scripts/checklists.py`, and offline unit tests in `skills/awesome-checklists/tests/`. It is discoverable through `npx skills add https://github.com/Pro-GenAI/awesome-checklists`, including Codex and Claude Code agent targets. This repository is public; anonymous installation and live checklist retrieval are supported subject to GitHub rate limits. Credentials are optional for readers.

**Skill files are agent instructions and tooling, not new checklist domains or checks.** Keep their security constraints, relative references, and documented commands in sync with existing scope routing and stable-ID conventions; do not duplicate checklist content or number skill files as checks. The website generator deliberately excludes `skills/` from the checklist/HTML inventory. Run `python3 -m unittest discover -s skills/awesome-checklists/tests -v` to validate helper behavior and package metadata. Run `python3 skills/awesome-checklists/scripts/validate_inventory.py` to verify expected per-scope counts, contiguous filenames, unchecked source templates, **visible per-check priority markers**, and globally unique stable IDs. Use `python3 skills/awesome-checklists/scripts/export_checklists.py --output checklists.json` for a full, offline, machine-readable catalog and optional project-review template. Run the unit tests after edits to checklist text, core selection metadata, or the exporter. The validator and exporter are local maintenance commands; GitHub Actions source lint is disabled as `.github/workflows/checklist-lint.yml.disabled`.

## Reusable project review badge

The hand-authored `website/assets/reviewed-with-awesome-checklists.svg` is a portable, accessible SVG badge, automatically included under `website/dist/assets/` during website builds. The root `README.md` documents a public Shields.io version (publicly displayable without requiring repository authentication), plus a self-hosted SVG alternative. The visible wording is **“Reviewed with awesome-checklists”**, paired with a prominent checkmark indicating that a checklist-based review took place—not that the project passed certification. The self-hosted SVG is 440 × 44 px for readability; the Shields.io option uses the larger `for-the-badge` style and includes a tick in the label.

**A badge is a voluntary project-maintainer self-declaration, not a third-party certification, endorsement, independent audit, or promise of compliance.** Do not imply Pro-GenAI has reviewed a project simply because the image is present. Recommend evidence-backed, project-specific reviews and clear records of exceptions, unresolved risks, and last review date. Do not add automated badge awards or misleading pass/fail claims without a separately defined verification process.
