## MCP agent protocol revision (targeted source update)

The current stable [Model Context Protocol specification is **2026-07-28**](https://modelcontextprotocol.io/specification/2026-07-28/index), which supersedes the November 2025 version. Its [changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog) documents the stateless core and authorization changes. Updated [general](../AI/11_AI_Agents_and_Tool_Orchestration.md) and [backend](../backend/17_AI_Agents_and_Tool_Orchestration.md) AGENT references on 2026-11-15. **Do not assume an installed SDK uses the latest revision**: verify negotiated protocol and SDK support before testing session, tool-discovery and authorization behavior.

## Practical cross-check of current checklists

- **AI governance (`AIG`):** The existing `AIG-019` already instructs reviewers to reassess EU AI Act deadlines. Keep the item; update its source guidance rather than inventing a duplicate ID. The NIST voluntary-status caveat remains appropriate.
- **AI security/red team (`SEC`/`RED`):** OWASP 2026 LLM and Agentic lists are appropriate for the domain. The generic shared/backend/frontend Security lists should not cite NIST AI-specific or WCAG sources solely from a copied reference block; those belong to relevant AI and Accessibility checklists.
- **AI agents (`AGENT`):** Threat and approval controls remain applicable; inspect current runtime permissions and side effects before marking an ID PASS.
- **AI human review (`AIG`/human oversight):** Regulatory human oversight applies only to relevant categories and deadlines; human sign-off for a project release remains a separate internal governance choice.
- **Remaining AI files:** Source-currency review of headline frameworks does **not** demonstrate completeness or accuracy of vendor SDK details, API releases, region-specific law, or all other citations. Keep original source dates for material not rechecked.

## Refresh process

For a material AI release or at least quarterly, check the four official source families, record the exact publication/version, date consulted, relevant changed clauses or risks, checklist IDs affected, owner, applicability and evidence. Add new checks only for independently verifiable gaps; preserve stable IDs and record successor/moved IDs in [ID history](id-history.md) and [CHANGELOG](../../docs/CHANGELOG.md). Reviewers must assess the current legal text, not merely a dated summary.
